title: '使用 WireGuard 进行组网'
description: '通过云端 WireGuard Hub、家庭侧 Peer 与远程客户端建立安全网络，介绍地址规划、配置、路由、验证和排障。'
---

WireGuard 是基于公钥的 VPN，可在互联网上的设备之间建立加密隧道。把多个 Peer 放入统一的私有地址规划后，便可以通过路由访问彼此或访问指定的内网网段。本文以“云服务器作为中心节点，家庭网关和远程设备作为 Peer”为例，说明如何组建一个可访问家庭 LAN 的网络。

本文侧重组网原理与配置骨架。不同 Linux 发行版、防火墙、家庭路由器和云服务商的操作命令会有差异；请根据自己的系统补齐持久化转发与防火墙规则。不要把示例配置未经检查直接用于生产环境。

## 1. 目标拓扑

家庭网络通常在 NAT 路由器后面，没有可直接从公网访问的地址。让家庭侧节点主动连接云服务器，可以避免在家庭路由器上为 VPN 服务开入站端口：

```text
远程电脑 / 手机
21.98.0.10 / 21.98.0.9
       │
       │ WireGuard 加密隧道，UDP 51820
       ▼
云端 Hub：21.98.0.1
       │
       │ WireGuard Peer（家庭侧主动建立连接）
       ▼
家庭网关：21.98.0.2
       │
       │ 家庭 LAN 路由
       ▼
家庭设备：192.168.5.0/24
例如 PVE：192.168.5.3
```

在这个拓扑中，云服务器只负责中心转发。要访问家庭 LAN，家庭侧还需要一个始终在线的 WireGuard Peer 作为路由节点。它可以是 Linux 主机、虚拟机或支持 WireGuard 的路由器，并且必须能够转发 VPN 与 LAN 之间的流量。仅在云服务器和笔记本之间建立隧道，不能自动访问云服务器以外的家庭网段。

如果只需要让远程设备访问云服务器本身，可以省略家庭侧节点和 LAN 路由，使用更简单的客户端到服务器配置。

## 2. 地址规划

下面使用文档示例地址：

| 节点 / 网络 | 示例地址 | 说明 |
| --- | --- | --- |
| WireGuard 网段 | `21.98.0.0/24` | VPN 内部使用的私有网段 |
| 云端 Hub | `21.98.0.1/24` | 有公网地址，监听 WireGuard UDP 端口 |
| 家庭网关 Peer | `21.98.0.2/24` | 将 VPN 流量路由到家庭 LAN |
| 手机客户端 | `21.98.0.9/32` | 独立客户端地址 |
| 电脑客户端 | `21.98.0.10/32` | 独立客户端地址 |
| 家庭 LAN | `192.168.5.0/24` | 应避免与客户端常用网络重叠 |
| 家庭 PVE | `192.168.5.3` | 示例内网管理地址 |

确保 VPN 网段不与云端、家庭 LAN 或远程客户端所在网段冲突。`/24` 表示一个网段；Peer 上的 `/32` 表示单个 IPv4 主机地址。

## 3. 安装 WireGuard 并生成密钥

在云端、家庭网关和每个客户端分别安装 WireGuard 工具。Debian / Ubuntu 可使用发行版的软件包：

```bash
sudo apt update
sudo apt install wireguard
```

在每台设备上分别生成密钥对。以下命令应在对应设备上执行，私钥不要离开设备：

```bash
umask 077
wg genkey | tee private.key | wg pubkey > public.key
```

将公钥安全地登记到对端配置中。公开文档、截图和代码仓库中不要放真实私钥、服务器密码、FRP Token 或部署凭据。示例中的尖括号占位符都需要替换。

## 4. 配置云端 Hub

云端 `/etc/wireguard/wg0.conf` 示例：

```ini
[Interface]
Address = 21.98.0.1/24
ListenPort = 51820
PrivateKey = <云端私钥>

# 家庭网关：负责 192.168.5.0/24
[Peer]
PublicKey = <家庭网关公钥>
AllowedIPs = 21.98.0.2/32, 192.168.5.0/24

# 电脑客户端
[Peer]
PublicKey = <电脑客户端公钥>
AllowedIPs = 21.98.0.10/32

# 手机客户端
[Peer]
PublicKey = <手机客户端公钥>
AllowedIPs = 21.98.0.9/32
```

云端 Peer 中，家庭网关的 `AllowedIPs` 同时声明它的隧道地址和它后方可达的家庭网段。每个远程客户端则只声明自己的 VPN 地址。不要在多个 Peer 上重复分配同一个地址或网段，否则路由归属会变得不明确。

## 5. 配置家庭网关

家庭侧 Linux 网关的 `wg0.conf` 示例：

```ini
[Interface]
Address = 21.98.0.2/24
PrivateKey = <家庭网关私钥>

[Peer]
PublicKey = <云端公钥>
Endpoint = <云服务器公网地址>:51820
AllowedIPs = 21.98.0.0/24
PersistentKeepalive = 25
```

家庭网关通常位于 NAT 后面，所以由家庭侧主动向云端发起连接。`PersistentKeepalive = 25` 可帮助维持 NAT 映射，常用于这类长期待机的 Peer；具体间隔可按网络环境调整。

家庭网关还要开启 IPv4 转发，并允许 `wg0` 与家庭 LAN 网卡之间按需要转发。Linux 上可临时启用转发用于验证：

```bash
sudo sysctl -w net.ipv4.ip_forward=1
```

临时设置重启后会失效。正式部署时，应按发行版方式持久化，并用 nftables、iptables、ufw 或 firewalld 配置最小范围的转发规则。不要为了快速连通而关闭整台服务器的防火墙。

## 6. 配置远程客户端

电脑或手机分别使用独立密钥与地址。电脑示例：

```ini
[Interface]
PrivateKey = <电脑客户端私钥>
Address = 21.98.0.10/32

[Peer]
PublicKey = <云端公钥>
Endpoint = <云服务器公网地址>:51820
AllowedIPs = 21.98.0.0/24, 192.168.5.0/24
PersistentKeepalive = 25
```

此处的 `AllowedIPs` 表示将 VPN 网段与家庭 LAN 的流量送入隧道。它采用分流模式，普通互联网流量仍从客户端本地网络直接出去。若将其设置为 `0.0.0.0/0`，则所有 IPv4 流量都会交给 VPN，需要额外设计云端出口转发、NAT 和 DNS；不要在没有配置这些环节时直接改成全隧道。

## 7. 路由与回程流量

数据包到达目标主机后，响应也必须有路返回。家庭 LAN 通常只知道自己的默认网关，不知道 `21.98.0.0/24` 在哪里。可选两种常见方案：

### 方案 A：在家庭路由器添加回程路由

在家庭路由器添加静态路由：

```text
目标网段：21.98.0.0/24
下一跳：家庭 WireGuard 网关在 LAN 上的地址
```

这样家庭设备能看到 VPN 客户端的真实源地址，日志和访问控制更清楚。前提是家庭路由器支持静态路由，且家庭网关有固定 LAN 地址。

### 方案 B：在家庭网关对 VPN 来源做 SNAT

如果家庭路由器不能配置静态路由，可在家庭 WireGuard 网关上将来自 VPN 的流量 SNAT 成该网关的 LAN 地址。家庭设备的响应便会返回到网关，再由连接跟踪还原并送回 VPN。SNAT 规则需要结合实际 LAN 接口、VPN 接口和防火墙框架配置；它会隐藏家庭设备看到的客户端 VPN 源地址。

两种方式通常择一作为回程方案。无论采用哪种，云端和家庭网关的 IP 转发、防火墙放行及 WireGuard Peer 路由仍必须匹配。若只配置客户端 `AllowedIPs`，去程可能进了隧道，但回程仍可能失败。

## 8. 启动与验证

在 Linux 节点启动接口并设为开机启动：

```bash
sudo systemctl enable --now wg-quick@wg0
sudo wg show
```

云端安全组和主机防火墙需要允许 WireGuard 实际使用的 **UDP** 端口，例如 `51820/udp`。家庭网关主动连接云端时，通常不需要在家庭路由器开放入站 WireGuard 端口。

按以下顺序逐层验证：

1. 在云端使用 `sudo wg show` 查看 Peer 最近握手时间和收发字节数。
2. 客户端访问 `21.98.0.1`，验证客户端与云端隧道。
3. 客户端访问家庭网关的 VPN 地址 `21.98.0.2`，验证云端到家庭 Peer 的路径。
4. 客户端访问家庭网关的 LAN 地址及其他家庭主机，例如 `192.168.5.3`。
5. 测试实际服务端口，例如在浏览器访问 `https://192.168.5.3:8006`。

Ping 可能被防火墙禁用，因此 Ping 失败不能单独证明 WireGuard 隧道失败。应结合握手、流量计数和实际 TCP 服务连通性判断。

## 9. 分层排障

| 现象 | 优先检查 |
| --- | --- |
| 没有最近握手 | Endpoint、公钥、私钥是否配对、UDP 端口、安全组、WireGuard 服务状态 |
| 有握手但 VPN 地址不通 | 两端 `Address`、Peer `AllowedIPs`、主机防火墙和 ICMP 策略 |
| 能访问云端，不能访问家庭网关 | 家庭 Peer 是否在线、云端家庭 Peer 的路由声明、云端 IP 转发 |
| 能访问家庭网关，不能访问其他 LAN 主机 | 家庭网关转发规则、家庭 LAN 路由、目标主机防火墙 |
| 请求到达但没有响应 | 回程路由或 SNAT、家庭默认网关、连接跟踪和防火墙状态规则 |
| 主机可达但某个服务不通 | 服务是否监听目标地址和端口、服务自身防火墙、TLS 或应用配置 |

路由可在 Linux 上用 `ip route` 查看，在 Windows 上用 `route print` 查看。WireGuard 的状态用 `sudo wg show` 查看；UDP 监听情况可用 `sudo ss -lunp` 查看。具体服务单元名称可能随安装方式变化。

## 10. WireGuard 与 FRP 的分工

WireGuard 建立受控的私有网络；FRP 则把明确指定的内网服务通过反向隧道映射到公网。它们不是同一种工具，可以按访问对象分工：

| 访问对象 | 常见方式 |
| --- | --- |
| PVE、数据库、缓存和内部管理服务 | WireGuard 接入后走私网地址 |
| 面向访客的网站 | 域名、HTTPS、Nginx 与必要的后端代理 |
| 特定自动部署流程或必须公开的 TCP 服务 | 按需保留 FRP 映射，并限制访问来源与权限 |

例如，家庭服务器环境可以继续使用云端 Nginx 和 FRP 提供公开博客，同时让 PVE 管理只通过 WireGuard 访问。部署端口、FRP 控制端口、WireGuard UDP 端口用途不同，应分别核对配置和防火墙规则，不要依据历史端口号照抄。

## 安全要点

- 每个 Peer 使用独立密钥和地址；设备遗失或停用时撤销对应 Peer。
- 只在云防火墙和主机防火墙开放必要端口。WireGuard 默认使用 UDP。
- 限制 Peer 的 `AllowedIPs` 与转发范围，避免不必要的网段互通。
- VPN 只提供网络层通道，PVE、数据库和业务服务仍需认证、授权与更新维护。
- 公共文档、代码仓库和截图中隐藏私钥、访问令牌、密码及可识别的设备凭据。

## 小结

通过云端 Hub、家庭侧路由 Peer 和远程客户端，可以在不直接暴露家庭管理端口的前提下，让可信设备访问家庭 LAN。组网成功依赖的不只是隧道握手，还包括 Peer 路由、IP 转发、防火墙规则和返回路径。排查时从握手开始，一段一段验证，能更快定位问题所在。
